## 2. Findings & Análise Agregada

### 2.1 Visões Agregadas e Invariantes Arquiteturais

1. **Isolamento de Domínio e Arquitetura Hexagonal:**
   - O ecossistema headless (`/api/v1/*`) foi construído sobre a camada de domínio existente sem duplicar lógica de negócio nem violar o princípio de neutralidade de mercado.
   - Os endpoints delegam diretamente para os serviços canônicos (`CourierProfile`, `StoreProfile`, `JobPost`, `BidAsk`).

2. **Princípio Fundamental de Taxa Zero (Zero-Fee Commitment):**
   - As chamadas de API e os Webhooks não impõem qualquer taxa percentual ou custo de intermediação sobre os fretes contratados pelos parceiros B2B.

3. **Segurança e Isolamento Multi-Tenant (NFR-5):**
   - Todas as tabelas criadas (`api_clients`, `webhooks_subscriptions`) possuem Row Level Security ativado.
   - As chaves de API trafegam em texto claro apenas na geração; o banco de dados armazena estritamente o digest SHA-256 (`api_key_hash`), impedindo vazamento de credenciais mesmo em caso de dump de leitura.

4. **Resiliência e Erros Padronizados (RFC 7807):**
   - Todas as respostas de erro (400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 429 Too Many Requests, 500 Server Error) seguem rigorosamente a RFC 7807 (`type`, `title`, `status`, `detail`).

5. **Performance e Ergonomia (NFR-4 e NFR-9):**
   - O Web Component `<delivrery-button />` não possui dependências de framework em tempo de execução e monta em $< 50\text{ms}$.
   - Todos os elementos interativos do portal e do botão atendem a $\ge 48\text{px}$ de altura mínima de toque.
